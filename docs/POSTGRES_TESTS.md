# Disposable PostgreSQL budget verification

`npm run test:postgres` uses the pinned Evidence PostgreSQL driver and canonical migration with separate restricted authenticated TCP sessions on a CI-owned PostgreSQL17 fixture. Four groups cover competing reservations, one-use effect consumption, post-COMMIT lost acknowledgement/fresh-pool recovery, and cached command authorization after a directly observed project-lock wait. The last case changes stored membership through a trusted fixture-only write; it does not introduce or qualify a membership-administration endpoint.

Fixture admission requires `RCO_TEST_DISPOSABLE_POSTGRES=1` and a loopback `RCO_TEST_ADMIN_URL` naming the empty database `resources_ci`, with the migration username `postgres`. Remote/query/fragment targets and preexisting ledger schemas are refused; the fixture never resets a database. Runtime operations use an independent restricted LOGIN with only evidence_runtime membership. Backend PIDs and session_user are asserted. Fixed fixture passwords are not production credentials. No live provider requests, payments, sensitive data or paid infrastructure are used.

The lock case observes pg_stat_activity and pg_blocking_pids through the fixture admin connection before releasing a membership change. It must see an actual blocked backend; elapsed time is not substituted for contention evidence. Receipt verification is a controlled test callback, not live provider attestation. PostgreSQL/Docker are unavailable locally: typecheck and four invalid-target admission cases can run here, but actual network success must come from current-head CI. Production TLS, failover, throughput, host identity, real receipt services and deployment remain unqualified.
