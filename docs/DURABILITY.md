# Durable budget adapter — implementation checkpoint

The store reuses a pinned Evidence persistence SDK in a separate dedicated resource database. It does not share Evidence or intake operational databases. Scope-bound manager policy creates budgets; only registered budget operators can load or mutate them. Commands compare the actual storage revision and bind replay keys to authenticated actor, purpose-bearing payload and expected revision.

Balances, hash-chained domain entries, immutable storage revisions, audit and change-outbox records commit together. Attempted effects require a deployment-configured receipt verifier before settlement or release. A reference alone does not establish a charge/no-charge outcome. No default verifier is provided. Verification is time-bounded and receives an abort signal; failures/timeouts roll back without exposing raw provider errors.

`consumeEffect` changes a committed reservation to uncertain in one transaction before returning a one-shot description. It has no idempotent replay path that can issue a second description. A lost response requires reconciliation. Actual external transports remain a separate trusted gateway; this store cannot stop code that independently possesses a provider credential from calling it directly.

Validation: eight actual-migration restricted-login PGlite integration tests plus six domain tests pass locally, with strict typecheck, compiled build and registry validation. This covers rollback, revision contention under a serialized embedded connection, receipt rejection, lost acknowledgements, scope and caller-input mutation. It does not establish independent network-session contention. CI, live receipt/provider verification and operational acceptance remain separate. No live payment, provider call or credential provisioning occurs.

Receipt callback admission and result acceptance both use a monotonic deadline, in addition to the timeout timer. A callback that blocks the event loop cannot make a late `true` result valid by delaying that timer. Abort signals are closed on every exit, late resolution cannot resume settlement, and callback exception diagnostics remain sanitized. This deadline cannot preempt blocked JavaScript, undo callback side effects or bound a database transaction already in progress; host isolation and independent receipt-service qualification remain required.

Development checkpoint: 17 ordinary local tests, typecheck, build and registry pass. Three new restricted-migration groups cover the original late-acceptance regression, asynchronous late resolution, strict boolean results, callback DomainError sanitization and AbortSignal cleanup. The regression failed on the previous source and passes with the monotonic gate. All eleven store groups also execute successfully through the installed compiled public package. Final-head CI remains required before merge. No provider requests or payments are made.
